# Population Enrichment (PC) - Simple-Case Design Specification

Status: Final D1 sign-off candidate for issue #97

## Purpose

This document defines the simple population-enrichment analysis logic for the
p-value combination method in the first implementation slice:

- 1 treatment arm
- 1 endpoint
- 2 populations (full and subgroup)
- non-interactive analysis first

It provides canonical hypothesis ordering, stage-1 alpha split behavior,
adaptation rules, and testable outputs.

## Scope

In scope:

- Analysis logic for p-value combination (inverse normal)
- Canonical ordering and naming for hypotheses
- Stage-1 alpha split for full vs subgroup families
- Simple adaptation decisions after look 1

Out of scope:

- Simulation changes
- CER changes
- Survival endpoint changes

## Canonical Hypothesis Ordering

For the simple case (1 treatment, 1 endpoint, 2 populations), the canonical
hypothesis ordering is:

1. H1: Full population treatment effect on endpoint E1
2. H2: Subgroup population treatment effect on endpoint E1

The ordering is aligned with the population-enrichment reference diagrams under
docs/pop enrich and must be used consistently in:

- analysis design
- examples and fixtures
- tests
- any interactive display/output

## Stage-Wise Structure

Assume two looks with cumulative information fractions:

- Look 1 at information fraction t1
- Look 2 at information fraction t2 = 1

Stage-wise efficacy boundaries are generated by rpact from:

- one-sided alpha
- info_frac
- typeOfDesign and related spending parameters

The stage-wise p-value cutoffs are the values used by analysis at each look.

## Stage-1 Alpha Split Behavior (Simple Case)

For the first enrichment implementation slice, use a fixed family split at
look 1:

- Full population family share: 70%
- Subgroup family share: 30%

In the two-node graph form this corresponds to:

- WI = c(H1 = 0.70, H2 = 0.30)

Graph transitions must preserve valid graph-based multiple-testing behavior.
If no special transition is required for a scenario, use a symmetric
two-hypothesis transition matrix:

- G = matrix(c(0, 1, 1, 0), byrow = TRUE, nrow = 2)

## Adaptation Rules After Look 1

Simple-case post-look-1 adaptation options:

1. Continue both populations to look 2.
2. Enrich to subgroup-only continuation:
   - drop H1 (full population)
   - continue with H2 only

Constraints:

- Adaptation inputs are not valid at look 1.
- Selection/modification/correlation updates can be applied only before
  analyzing look > 1.

These constraints match existing API behavior and should remain explicit in
simple-case design documentation.

## Correlation Assumptions

For normal endpoint simple-case analysis, full/subgroup test statistics are
correlated due to nested populations.

Use Martin's nested-population correlation formulation:

rho = sqrt((1 / n_d + 1 / n_0) / (1 / m_d + 1 / m_0))

where:

- n_d, n_0 are full-population treatment/control sizes
- m_d, m_0 are subgroup treatment/control sizes

When correlation entries are unknown (NA), analysis must still avoid invalid
multivariate calculations by partitioning into cliques of known pairwise
correlations.

## Input Contract (Simple Non-Interactive Flow)

Setup inputs:

- WI, G
- test.type
- alpha
- info_frac
- typeOfDesign and optional spending parameters
- Correlation (required for parametric tests)

Per-look inputs:

- p_raw for active hypotheses
- optional selection/new_weights/new_G/new_correlation for look > 1

## Expected Outputs

At minimum, each look should produce and/or update:

- CurrentLook
- IndexSet (active hypotheses)
- AdjPValues and AdjPValueTable
- rej_flag_Curr and rej_flag_Prev
- WH / WH_Prev (intersection weights)
- boundary table and inverse-normal weights from setup
- trial completion status

## Explicit Acceptance Thresholds

The D1 design sign-off is accepted only if all thresholds below are met.

1. Canonical-ordering invariance threshold
- H1 and H2 definitions must remain fixed across setup, analysis, and output.
- Acceptance criterion: 100% agreement of ordering labels across documentation,
   test scaffolds, and any fixture metadata used by T1.

2. Stage-1 alpha split threshold
- The simple-case stage-1 family split is fixed as full/subgroup = 0.70/0.30.
- Acceptance criterion: WI must be exactly c(H1 = 0.70, H2 = 0.30) for D1/T1
   baseline scenarios.

3. Stage-wise boundary consistency threshold
- Stage boundaries must be generated from rpact using the declared design
   parameters and info fractions.
- Acceptance criterion: the analysis boundary table and design object boundary
   values must match to within absolute tolerance <= 1e-12.

4. Correlation input validity threshold
- Correlation matrices used in simple-case examples must be symmetric and have
   unit diagonal entries.
- Acceptance criterion: max(abs(Corr - t(Corr))) <= 1e-12 and
   max(abs(diag(Corr) - 1)) <= 1e-12.

5. NA-correlation robustness threshold
- If unknown correlations appear (NA), evaluation must proceed via safe clique
   partitioning without invalid pmvnorm blocks.
- Acceptance criterion: no clique passed to multivariate adjustment contains
   any NA off-diagonal pair.

6. Look-1 adaptation guardrail threshold
- Adaptation arguments are not allowed at look 1.
- Acceptance criterion: look-1 calls with selection/new_weights/new_G/
   new_correlation must fail deterministically with explicit validation errors.

7. End-to-end scenario reproducibility threshold
- Each T1 seed scenario must produce stable state transitions for active set,
   rejection flags, and adjusted p-value table shapes.
- Acceptance criterion: repeated runs with identical inputs yield identical
   state transition artifacts.

## D1 Acceptance Checklist

Issue #97 is considered complete when this design is represented and agreed:

1. Canonical H1/H2 ordering is explicit and stable.
2. Stage-1 alpha split (70/30) is explicit for the simple case.
3. Allowed post-look-1 adaptation paths are explicit.
4. Correlation assumptions for nested populations are documented.
5. Expected input/output contracts are documented for non-interactive analysis.
6. Test-ready scenarios are enumerated for T1.

## Decision Log

### D1-DEC-001 (2026-07-25)
Decision: Lock the simple-case canonical order as H1 = full population and
H2 = subgroup population for 1 treatment x 1 endpoint x 2 populations.

Rationale: This preserves alignment with population-enrichment reference
material and prevents test/fixture ordering drift.

Impact:
- T1 scenarios and fixtures must use this exact order.
- Any future API option to reorder labels is out of scope for D1.

### D1-DEC-002 (2026-07-25)
Decision: Use fixed stage-1 alpha split 70/30 (full/subgroup) for the first
implementation slice.

Rationale: A fixed split enables deterministic baseline validation and keeps
the first analysis increment minimal.

Impact:
- D1/T1 baseline WI uses c(H1 = 0.70, H2 = 0.30).
- Configurable split is deferred to later scope.

### D1-DEC-003 (2026-07-25)
Decision: For look > 1, allow both continuation paths (keep both populations
or enrich to subgroup-only) while rejecting any adaptation inputs at look 1.

Rationale: Matches current non-interactive API constraints and avoids
ambiguity at the first look.

Impact:
- Validation tests must include look-1 adaptation guardrail coverage.
- Selection/strategy update behaviors remain post-look-1 only.

### D1-DEC-004 (2026-07-25)
Decision: Treat NA correlations as valid input patterns requiring safe clique
partitioning rather than forcing complete correlation matrices.

Rationale: Population-enrichment structures can naturally produce unknown
correlation pairs.

Impact:
- T1 coverage must include at least one NA-correlation robustness scenario.
- Downstream code must preserve clique-safety expectations.

## Test-Ready Scenarios for T1

1. Baseline continuation: H1/H2 both continue to look 2.
2. Enrichment continuation: H1 dropped after look 1, H2 continues.
3. Guardrail: adaptation arguments at look 1 must error.
4. Correlation robustness: NA patterns that require clique partitioning still
   produce valid adjusted p-value flow.
